# 课程要求与范围

**来源分开看：**老师的《实验作业第1组 Hadoop安装部署与实例演示.txt》定义课程任务；《Hadoop 小组实验任务分工.pdf》《Hadoop 小组项目开发规则.pdf》是本组分工和协作规则。下表不把小组自定要求当成老师原话。

## 1. 已确认的时间与部署方式

组长于 2026-10-20 确认：老师接受 Docker 部署，截止日期为 **2026-11-03**，视频总长 **80—120 分钟**，每人讲解约 **10 分钟**。TXT 中“汇报 45 分钟”原针对 5 人组；7 人组汇报总时长如无另行通知，录制前仍需核对，不能将每人约 10 分钟直接当成视频总长要求。

Windows 上 Docker 使用 WSL2 提供 Linux 环境，容器共享内核；本组以一台电脑的三个独立容器完成多节点实验。Docker 的接受已确认，不再作为待确认事项。

## 2. 老师要求对应谁交付

| 老师任务 | 本组交付 | 负责人 | 验收证据 |
| --- | --- | --- | --- |
| Linux 环境、JDK/Hadoop 安装部署 | 已获认可的 Docker 方式；说明基础 Linux、Java/Hadoop 安装和环境配置 | 1 号 | Dockerfile、构建/版本验证记录、安装配置讲解 |
| 单机模式 | 本地文件系统上的 Hadoop 作业 | 5 号 | 输入、执行命令与正确输出 |
| 伪分布式 | 一个节点的 NameNode/DataNode 与 HDFS 操作 | 5 号 | 进程、节点注册、读写及重启结果 |
| 完全分布式 | master、worker1、worker2，HDFS/YARN 服务分布 | 2、3、4 号 | 服务注册、数据读写与实际作业 |
| WordCount 实例配置与演示 | 官方自带例子 + 本组实现的完整统计流程 | 4、6 号 | 官方样例对照、自有源码、词频与作业证据 |
| MergeFile 实例配置与演示 | 按 7 号提出、组长确认的方案实现多文件处理 | 7 号 | 方案、固定输入/预期、真实运行结果 |
| PPT 与含字幕配音的视频 | 各人提交本模块内容，组长统稿与合成 | 全员，1 号汇总 | 完整文件、章节、字幕配音和时长核对 |

## 3. 小组额外统一的要求

GitHub PR 审核、固定镜像与公共接口、1 Master + 2 Worker、双 Worker 数据/计算参与、build/run/verify 脚本和重启持久化来自小组分工与规则，用于保证可以合并和复现。

老师 TXT 没有要求两个实例在三种模式中各跑一遍。本组验收为：5 号完成两种模式，6、7 号在完全分布式环境完成实例；若教师另有补充，再更新范围。

## 4. MergeFile 方案尚待 7 号交付

2026-10-20，组长选择“先由 7 号提出方案”。TXT 没有指定是否去重、排序。7 号须提交规则、至少两份输入和唯一预期，组长确认后再冻结验收。

当前镜像 Hadoop 3.3.6 的 examples JAR 已检查：包含 WordCount，没有名为 MergeFile 的示例类。老师使用了“自带实例”的表述，不能据此编造一个可直接调用的 mergefile 子命令；7 号应说明参考来源与实现方式，必要时向老师核对指的是哪份实例。

具体任务见 [成员指南](modules/README.md)，日期安排与完整交付见 [最终验收清单](final-acceptance.md)。公共底座实测结果见 [验证记录](phase0-status.md)，成员正式模块仍待开发验收。
