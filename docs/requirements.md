# 需求来源与验收核对

本次读取了用户提供的老师 TXT、26 页任务分工 PDF、21 页项目开发规则 PDF。它们作为需求资料使用；本次实施范围以用户明确要求的“仅组长 Phase 0”限定。

## 已确定的项目范围

- 1 号：统一基础环境、框架、公共接口、仓库；中后期最终集成。
- 2 号：1 Master + 2 Worker 的完全分布式编排。
- 3 号：HDFS 数据分布，两个 DataNode。
- 4 号：YARN / MapReduce，两个 NodeManager。
- 5 号：单机及伪分布式。
- 6/7 号：WordCount / MergeFile。

## 需组长确认的课程验收差异

老师 TXT 写的是“安装 Linux 虚拟机”，列出的虚拟化软件包括 VirtualBox / VMware / Parallels；小组资料改用 Docker。Docker 方案的环境已按小组计划准备，但最终应确认老师接受容器方式；若要求真正的 Linux 虚拟机，补充这一部署与展示环节，不能把 Docker 演示直接视为该项完成。

老师 TXT 的视频 80–120 分钟、汇报 45 分钟等指标针对“5 人小组”；目前小组为 7 人，不自动将这些指标视为 7 人最终要求，也不自行更改。请向老师确认 7 人对应时长。

老师要求两种实例演示以及 PPT、含字幕配音的视频，这些属于后续各模块交付，本次不生成。MergeFile 的具体处理语义由 7 号在实现前结合课程材料澄清。

## 公共底座验收门槛

1. 目录与 `.development`、文档一致。
2. 基础镜像能从 Dockerfile 构建，下载校验通过。
3. 镜像内 Java、javac、Hadoop 版本符合契约，能编译加载 Hadoop API。
4. 基础入口不自动格式化或启动集群。
5. 组长确认后记录镜像 ID、创建稳定提交与 `v0.1-bootstrap`；当前运行门槛待验证。
