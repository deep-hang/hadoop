# 成员 5 增强网页：环境、存储与对照解释

本轮为独立新增入口，原 `web.*`、`console.*`、`manage.*` 保留原逻辑。生产环境使用 Python 3.10+ 标准库和原生网页资源，不需要 npm 或第三方 Python 包。

## 启动

先启动 Docker Desktop Linux 引擎，然后从任意 PowerShell 目录执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "D:\Workspace\01_Study\bigData\hadoop\modes\standalone\web-plus.ps1"
```

也可双击 `modes/standalone/web-plus.cmd`。Git Bash、Mac/Linux 使用：

```bash
bash /path/to/hadoop/modes/standalone/web-plus.sh
```

支持 `--port`、`--no-open`、`--max-input-bytes`，含义与旧网页相同。默认仅监听 <http://127.0.0.1:19875/>，输入上限 1 MiB。

新旧网页共享同一个仓库级锁。已有网页正在运行时，先等待活动任务结束，再在其启动窗口按 Ctrl+C；之后启动增强入口。指定不同端口不能绕过仓库独占锁。

## 建议的核验顺序

1. 首页查看 Docker、统一镜像、HDFS 状态及检查时间。首次进入会异步执行一次完整检查，输入区仍可编辑。
2. 填入 `hello hadoop`，换行输入 `hello 你好 世界`。单机应得到 `hello=2`，其他三个词各 1 次，总词数 5。
3. 查看执行过程和“数据存放在哪里”，展开本地输入输出、宿主机目录及实际 Docker 挂载来源。
4. 点击“查看实际输入／输出”，在固定浏览页预览文件。文件浏览只读，不提供任意路径或 shell。
5. 返回首页输入或上传 TXT，选择伪分布式。若 HDFS 已停止，点击首页“启动 HDFS”；启动期间保持当前输入，成功后继续提交。
6. 已有初始化数据时只需启动。真正首次使用则到环境管理明确初始化，再启动。普通作业绝不自动格式化。
7. 点击双模式对照，查看共同输入校验值、两侧独立验证、实际存储路径和完整词频比较。
8. 查询历史、重新验证、下载 TSV、日志或新版本离线报告 ZIP。

没有新增浏览器草稿持久化。页面内部切换及首页启动服务会保留内存中的输入；刷新首页仍会清除未提交内容，已提交输入可从记录恢复。

## 环境状态怎么理解

- Docker 和镜像状态来自实际检测。Docker 无法连接时，依赖项显示未确认，不能推断镜像不存在。
- 轻量状态约每 10 秒更新，多个标签页共用检测结果。
- “HDFS 已就绪”要求完整检查确认 NameNode、DataNode、1 个 Live DataNode、安全模式关闭及根目录可访问。
- 完整证据超过 60 秒显示待刷新。容器处于运行中不等同于 HDFS 已通过检查。
- 完整检测、作业、验证、文件读取及服务操作共用耗时任务互斥通道。忙碌时显示当前任务链接，不建立后台队列。
- 初始化状态未确认时，不会根据“已停止”推断需要格式化。初始化、停止、移除容器继续要求明确确认；移除容器保留数据卷。

## 存储过程与证据

| 内容 | 单机 | 伪分布式 |
| --- | --- | --- |
| 文件系统 | `file:///` | `hdfs://pseudo:9000` |
| 计算 | 临时客户端中的本地 MapReduce | 临时客户端中的本地 MapReduce |
| 输入输出 | `runtime/member5/standalone/<id>/input`、`output` | `/project/input/member5/<id>`、`/project/output/member5/<id>` |
| 常驻服务 | 无 | NameNode、DataNode |
| 实际存储 | 本模块运行目录的绑定挂载 | 本项目专用卷中的 HDFS 数据 |

临时客户端仍存活时，新增适配层核对 Compose 项目及本次调用标签，再读取真实挂载。HDFS 同时记录实际配置与所属服务卷。Docker Desktop 可能将 Windows 目录报告为 Linux 共享路径，页面分别列出本机仓库定位和 Docker 原始挂载来源。

NameNode 管理文件与数据块位置，DataNode 保存实际数据块。HDFS 逻辑文件与卷内数据块不是同名的一一映射；NameNode 不承担本地 MapReduce 的计算。

所有新增证据都有采集时间。旧记录缺少挂载信息时显示未记录，不用当前环境补写历史。说明流程不等于成功执行，阶段成功仍来自真实事件。

## 失败、诊断与重跑

失败页展示失败阶段、已确认原因、原始错误及下一步操作。已知检查采用明确错误类别；未知错误保留原文，不按日志关键词猜测。

验证失败后，诊断使用原 Java `InputCounts` 对保存快照独立计数，读取本次真实输出，列出缺词、多词、计数差异、重复行、格式错误和成功标记状态。差异按完整数据计算，网页每页 50 条，并可下载 TSV。

单机诊断读取实际本地文件字节：宿主机编辑可能使 Hadoop 的 `.crc` 过期，诊断仍需展示文件内容。此做法只用于诊断，不修改校验文件、不改变原验证入口，也不关闭 HDFS 的校验。

无法读取实际输出时明确显示无法取得结果，不使用历史成功 TSV 替代。诊断与失败证据按版本独立保存。下方词频若来自此前成功采集，会标明采集时间；最新验证结论单独展示。后续验证恢复后，旧诊断仍作为历史证据保留。

“恢复输入后重新运行”会创建新 ID，并登记原记录关系。已有输出不覆盖，失败记录不删除；没有自动重跑。

## 文件浏览与对照

HDFS 采用“输入／输出 → 运行目录 → 文件 → 预览”的固定页导航。支持运行 ID 搜索、每页 20 项、修改时间与时间来源。地址保存当前选择及上级分页条件，刷新或返回后可以恢复浏览位置。页面缓存标明读取时间，可点击“刷新实际数据”重新访问存储。

预览最多 64 KiB、200 行；空文件、缺失文件、空目录、目录缺失、服务不可用分别展示。中文、空格、`#`、`%` 等名称通过 Hadoop API 处理，不拆分 `ls` 文本。拒绝越界、符号链接和嵌套目录跳转。

对照结论依据运行时归档的共同输入、子记录及完整 TSV。两侧独立验证通过、输入一致、输出一致才通过；缺少一侧结果时显示尚不能比较。后续单模式验证不会改写历史对照结论。

阶段耗时来自各自事件。共同准备单独列出，整个 MapReduce 作为一个真实阶段；无独立证据的阶段不补造时间。入口耗时不能用作计算性能排名。

新增报告版本含存储说明、对照解释及当时诊断，ZIP 内提供 `explanation.json`。旧报告版本不覆盖。网页完整词频搜索和离线报告的原有展示上限规则继续适用。

## 数据、接口与测试

作业、输入与历史仍使用原成员 5 目录。新增附加证据位于各运行记录的 `plus/`，网页状态及日志仍在 `runtime/member5/web/`，开发验收证据在 `runtime/member5/web-plus-development/`。

新增查询：`/api/environment`、`/api/storage`、`/api/diagnostic`、`/api/comparison`。新增任务为 `environment` 和限定的 `local` 文件读取；HDFS 任务补充修改时间。查询接口读取缓存或已保存证据，耗时命令通过工作进程执行。

Host、同源、会话凭证和固定下载类型限制继续生效。新下载类型 `diff` 只提供已保存的差异 TSV。没有新增任意宿主机文件访问、任意命令、数据卷删除或持久化演示入口。

```powershell
python -B tests/standalone/test_web_plus.py
python -B tests/pseudo/check-web-plus.py
```

第二条使用随机 Compose 项目、专用卷和随机端口，结束后核对归属并清理测试资源。开发环境有 Node 时，可额外执行 `node tests/standalone/test_web_plus_ui.js`；生产运行不依赖 Node。

真实验收结果和未验证范围见 [本轮新增验收记录](WEB-PLUS-ACCEPTANCE.md)。所有提交仅保存在本地，推送及 PR 等待用户核验同意。
