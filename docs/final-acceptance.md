## 3. 组长补什么内容

- 安装配置演示：讲解 Docker/WSL2 的 Linux 环境、Dockerfile 如何取得固定 JDK/Hadoop、环境变量和目录；提供 [镜像构建](../docker/README.md) 与版本验证的实际记录。导入现成镜像只是组员接入步骤，不能替代整个安装配置讲解。
- 总体介绍：项目拓扑、任务分工、仓库结构、三个运行模式、模块之间的关系。
- 最终集成：按 [联合验证流程](member-onboarding.md#joint-check) 验证有依赖的 PR，测试通过后再合入 main；修复归属模块，由对应成员提交。
- 材料整合：统一 PPT 术语、图例和讲解顺序，检查每人的视频确有字幕和配音，最后合成并通看。

1 号的安装说明、总 PPT、总视频链接和最终复验结果统一记录在本文末尾，无需替成员重做其功能模块。

## 4. 最终一次完整复验

在新的源码目录和演示电脑上，由组长照已提交的说明操作。以下是待完成的验收清单，不是当前已通过的结果。

- [ ] 导入约定镜像，运行 verify；记录源码提交号和镜像 ID。
- [ ] 5 号单机：本地输入、任务执行、正确输出。
- [ ] 5 号伪分布式：一个 DataNode、文件读写、重启后数据保留。
- [ ] 2—4 号正式三节点：两个 DataNode、两个 NodeManager 就绪；Web 页面可查看。
- [ ] HDFS 文件正确读回，块/副本位置能对应两个 worker。
- [ ] 官方 WordCount 示例和 6 号自有 WordCount 均有正确结果与真实作业记录。
- [ ] 7 号 MergeFile 按已确认规则执行，固定结果一致。
- [ ] 两个应用都有多文件/分片演示，Map/Reduce 任务实际分布证据能对应 worker1、worker2；ApplicationMaster 日志不单独当作计算证据。
- [ ] 集群重启后原文件仍可读；再次运行使用新输出目录，输入不重复叠加。
- [ ] 各模式分别停止，测试没有删错数据卷；失败用例有非零退出码。
- [ ] 所有必要文件均在仓库，可从不同当前目录调用应用脚本；不依赖手改容器或个人未提交文件。
- [ ] 每个模块有说明、PPT、带字幕配音的视频；总视频 80—120 分钟。
- [ ] 最终 main 复验通过，记录最终提交号并由组长发布 v1.0-final；当前不提前标记为最终完成。

tests/integration/ 由 1 号整理实际联调命令和结果；待模块入口完成后再形成可运行的集成测试脚本，不放假成功脚本。

## 5. 视频、PPT 怎样汇总

建议总视频先按约 90 分钟安排：1 号 15 分钟，2/3/4 号各 12 分钟，5 号 15 分钟，6/7 号各 12 分钟。此分配是制作建议，最终总长必须在 80—120 分钟；每人约 10 分钟的讲解要求另按课堂汇报安排。7 人组汇报总时长仍需对照老师通知。

顺序：安装与总览 → 三节点编排 → HDFS → YARN → 单机/伪分布式 → WordCount → MergeFile → 总结。各段记录对应源码版本，录制前先跑通命令；剪辑后检查文字、配音和操作画面一致。

小型说明/截图放各模块目录；大型 PPT/视频放课程允许的文件共享位置或 Release 附件，在模块 README 写明文件名、版本、时长和访问链接。组长用未登录窗口检查分享权限，并下载完整最终材料做本地备份，不把镜像和大视频塞进 Git 历史。
